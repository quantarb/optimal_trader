# Multi-rate multi-asset transformer

## Latest-date warehouse notebook

`notebooks/trading_app_v2_multirate_live.ipynb` now calls
`quant_orchestrator.research_tools.warehouse_live.train_latest_warehouse_model`.
It uses the current warehouse multi-rate architecture and objectives from the
completed equities-only run, with fresh weights and a configurable market-cap
universe (default $10B). Training reads all stored history from 1900-01-01 through
the latest finite FMP equity close in the selected universe, including the current
partial year. The exclusive cutoff is the following day. The notebook does not
refresh market data or build/reuse the old corpus.

After training, it reuses the model and warehouse stream to produce one prediction
per equity priced on the common latest date. Current-year raw context is available
to the model, but other dates are not exported. Stale equities are listed in the
run summary. Same-date fitted predictions are deployment inputs, not an
out-of-sample backtest. Full supervised objectives, masked reconstruction and
next-token prediction remain enabled; option models and historical backtests are
not part of this workflow.

The runtime adapter calls `build_legacy_compatible_scores` so HITS hub/authority
percentiles match the established backtest score policy. It uses the saved
same-date equity closes, rather than refetching potentially newer prices.
`select_atm_options` reads exact-date warehouse chains for ranked eligible symbols.
For long signals it selects a call; for short signals a put. Selection minimizes
expiry distance from 60 calendar days, then strike distance from the same-date
close. Expiry ties prefer later expiry; strike ties prefer lower strike, then
contract identifier. No liquidity/ML/LLM score reranks the selection. Missing
chains or missing directional contracts are audited before trying the next equity.
The resulting table feeds the existing Alpaca order-plan adapter.

The first notebook cell controls training, universe, top-K and target DTE. Order
plan generation is optional (`BUILD_ORDER_PLANS=False` by default); enabling it
reads the existing accounts and live quotes but does not submit orders. The
existing Streamlit review/submission interface remains available. No LLM option
account is generated by this notebook's deterministic selection workflow.

Training artifacts live under `quant-orchestrator/artifacts/multirate_recovery/<universe>/latest_*`;
frontend artifacts live under `optimal_trader/artifacts/trading_app_v2/multirate_live/<universe>/latest_*`.

## Earlier multi-rate research implementation

The earlier reusable implementation lives under `scripts/multirate_transformer/`.
It provides:

- annual bidirectional issuer memory;
- quarterly bidirectional issuer memory conditioned on annual memory;
- a shared causal daily decoder with separate annual and quarterly cross-attention;
- asset-specific adapters for equity, corporate bonds/`note_bond`, preferred shares,
  warrants, and the other non-option classes represented by the existing related
  asset panels;
- dynamic task-head construction from the current MTL registry;
- raw HITS plus same-issuer and same-asset-class rank-label generation;
- point-in-time as-of alignment, masked ranking losses, and date-aware batches.

The authoritative feature-family audit is generated from the warehouse panel
`index.csv` and family metadata. For the current 1T cache, the generated report is:

`artifacts/multirate_transformer/feature_family_audit_1t.csv`

The resolved task inventory is:

`artifacts/multirate_transformer/task_inventory.csv`

The new warehouse adapter is `warehouse_data.py`. It consumes the same persisted
daily feature-family panels as the existing models, outer-joins family coverage,
filters the existing TA families, and derives causal annual/quarterly cadence
views from each row's preserved warehouse observation date. For raw warehouse
fundamental frames, `filing_date`/`accepted_date` can be normalized into that
observation date before constructing windows; fiscal period end dates are never
used as a substitute for availability.

Run the audits with:

```bash
python scripts/audit_multirate_transformer.py \
  --index <feature-family-cache>/index.csv \
  --output artifacts/multirate_transformer/feature_family_audit.csv

python scripts/audit_multirate_tasks.py \
  --output artifacts/multirate_transformer/task_inventory.csv
```
